## 2. Русский рил (фиксированный таймлайн)

### 0–2 с — обложка (cover)

- Только кликбейт-вопрос, **ВСЕ ЗАГЛАВНЫЕ**.
- Строка 1 — белый текст.
- Панчлайн (строка 2) — красный `#E31C23` с толстой белой обводкой:
  - `WebkitTextStroke` + `paintOrder: 'stroke fill'`.
- Футаж слегка затемнить.
- Этот кадр **и есть** обложка.
- **Без** аудио-CTA на обложке.

### 2–4 с

- Текст: «Как получить личный аудиоразбор от меня?»
- Красная вставка: «в конце видео».

### С 4 с — основная часть

- Лаконичные подписи **того, что она реально говорит**.
- Каждая подпись исчезает **через 1 с после последнего произнесённого слова**.
- **Никогда** не оставлять подпись висеть в тишине.

### Последние ~5 с — CTA

```
ХОЧЕШЬ бесплатный АУДИОРАЗБОР
пиши в комментариях
АУДИО
```

Слово **АУДИО** — красный `#E31C23`.

## 3. Английский рил

Тот же таймлайн и стиль обложки, но:

| Отличие | Правило |
|---------|---------|
| Текст на экране | Английский перевод речи, **не** русские субтитры |
| Голос | Клон Voicebox **Viki** (не generic TTS, не HeyGen-клон Victoria/Alena) |
| CTA | Слово **AUDIO** красным `#E31C23`, не «АУДИО» |

### Код (проект `taro-reel`)

- Точка входа EN: `src/index-en.ts`
- ID композиций **без подчёркиваний**, например: `IMG-4059-EN`
- Рендер: `--concurrency=2`

### Микс аудио (критично — баг от 17.08.2026)

**Проблема:** перекрывающиеся хвосты фраз при склейке.

**Решение:**

1. **Не** обрезать и **не** фейдить хвосты — это слова.
2. Микшер: полные WAV-файлы фраз.
3. Старт каждой следующей фразы:
   ```
   start = max(original_start, prev_end + ~0.28s)
   ```
4. Mux: беззвучное видео Remotion + `en-mix.wav` → **один** AAC-поток.
5. Русская дорожка в EN-версию **не** попадает.

## 4. Remotion: как писать код

### Композиции

- Одна композиция на клип / язык.
- Размер 1080×1920, fps и длительность — из исходника после монтажа.
- Тайминги обложки (0–2, 2–4, CTA в конце) — константы бренда; не дрейфовать.

### Субтитры и обложка

- Хранить таймкоды и текст в **данных** (JSON, массив объектов, `@remotion/captions` и т.п.).
- Компоненты только **читают** данные и рендерят по `useCurrentFrame()` / `Sequence`.
- Стили обложки (белый / красный `#E31C23`, обводка) — переиспользуемые константы или компоненты.

### Рендер

```bash
npx remotion render <composition-id> <output.mp4> --concurrency=2
```

Для EN после рендера — mux с `en-mix.wav` (один AAC).

### Чего избегать

- Субтитры, «нарисованные» инлайн-CSS без привязки к таймкодам.
- Подпись, переживающая паузу в речи.
- Смешивание RU-аудио в EN-экспорт.
- Обрезка/фейд хвостов фраз в микшере.

## 5. Карточка задания (job)

На каждый монтаж создавать файл:

```
video/jobs/YYYY-MM-DD-slug.md
```

`slug` — латиница, kebab-case, по смыслу клипа (например `2026-08-17-img-4059`).

### Шаблон

```markdown
# YYYY-MM-DD — <краткое название>

## Исходник
- Drive: «видео для монтажа» / <путь или имя файла>
- Локально (если есть): ...

## Заголовки
- RU (обложка, строка 1 CAPS): ...
- RU (строка 2, панчлайн): ...
- EN (cover line 1): ...
- EN (cover line 2): ...

## Субтитры / captions
- RU: <путь к файлу субтитров или ссылка>
- EN: <путь к файлу субтитров или ссылка>

## Аудио
- RU: оригинальная речь, денойз
- EN: Voicebox Viki; микс `en-mix.wav`; правило ~0.28s между фразами
- Заметки: ...

## Экспорт
- Composition ID (RU): ...
- Composition ID (EN): ...
- Drive: «Готовы видео GROK» / <имя = вопрос на обложке>
- Статус: [ ] RU  [ ] EN
```

Агент заполняет карточку **до** правок в Remotion и обновляет статус после рендера (рендер делает Hall).
